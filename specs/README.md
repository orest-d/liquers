# Liquers internal documentation

This folder holds the project's internal documentation: what the system is (`reference/`), how to
work on it (`guides/`), why each change was made (`design/`), what is wrong or missing
(`issues/`), and what was true on a date (`archive/`). Conventions — where a document goes, what
metadata it carries, how to file an issue — are in
[`DOCS_STRUCTURE_GUIDE.md`](DOCS_STRUCTURE_GUIDE.md). Every tracked document is indexed in
[`index.csv`](index.csv).

This page is the map: what exists, how far along it is, and which document to open. It is
maintained by hand; the marked blocks below are generated by `scripts/docs_index.py`.

> **Migration in progress.** The structure described here is being adopted; see
> [`DOCS_MIGRATION_PLAN.md`](DOCS_MIGRATION_PLAN.md) for what has moved and what has not. Until it
> completes, most documents are still at the top level of `specs/`.

## When to use what

| You want to… | Read |
|---|---|
| Understand the architecture and vocabulary | `reference/PROJECT_OVERVIEW.md` |
| Add a command | `guides/COMMAND_REGISTRATION_GUIDE.md` |
| Write tests | `guides/UNITTEST_GUIDE.md` |
| Know why something was built this way | the `design/<slug>/` for that capability |
| Know what is broken or missing | `index.csv` |
| File an issue | `DOCS_STRUCTURE_GUIDE.md` §4.8 |
| Know what a document is allowed to claim | `DOCS_STRUCTURE_GUIDE.md` §2 |
