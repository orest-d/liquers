# Every public name of the Python package has a docstring and a signature, and a test keeps it so

> **Complete on 2026-10-28**: implemented by automatic fix in #220.

Bulk design (`specs/guides/autonomous_bulk_design.md`), 2026-10-27: Phases 1-4 written. Split
from `design/py-api-reference/` (its former Phase 4 steps 1-6), which keeps the reference
generator.

## Phase 1: High-Level Design

### Purpose

`liquers` is mostly PyO3 classes whose methods carry no `///` comment, so `help()`, editors and
agents see bare names. This design documents every public name of the package and adds the
docstring half of the language-integration guide's `DOCS04` check, so coverage cannot regress.
A generated HTML reference is `py-api-reference`; it reads the docstrings this design writes. It
serves `VISION.md`'s "Better Python integration" priority.

### Problem Example

```python
help(lq.Query)              # method names only, no descriptions
lq.Query.encode.__doc__     # None
lq.KeyNotFoundError.__doc__ # None (generated by liquers/_errors.py `_install`)
```

Verified at HEAD (`04667a80`) by a source scan (a `///` comment attached to the item;
`#[new]`, `#[setter]`, dunder and `_`-prefixed items not counted). The counts are approximate:
two scans gave 285/238 and 295/247 methods, by slightly different rules.

| Kind | Public | Without a docstring |
|---|---|---|
| Registered classes (`liquers-py/src/lib.rs` `_native`) | 45 | 39 (all but `Environment`, `Issue`, `Context`, `State`, `AssetRef`, `EnumArgumentType`) |
| Their public methods and properties (incl. `#[pyo3(get)]` fields) | ~285-295 | ~238-247 (`MetadataRecord` 53, `AssetInfo` 25, `Metadata` 22, `Query` 19, …) |
| Native functions (`parse`, `parse_key` in `query.rs`; `build_plan` in `plan.rs`) | 3 | 3 |
| Generated error classes (27 variants, 3 categories) | 30 | 30 |
| Python-level names (`command`, `evaluate`, `LiquersError`, …) | 6 | 0 |

`grep -rn text_signature liquers-py/src` finds nothing. 51 public methods are `#[staticmethod]`
or `#[classmethod]` (e.g. `Expires.never`, `expiration.rs:20`); three fields use
`#[pyo3(get)]` (e.g. `Issue.message`, `environment.rs:456`, whose doc comes from the field).
`QuerySegment` (`query.rs:429`) is a `#[pyclass]` returned by `Query.segments` but not registered
and not in `__all__` (`PY-QUERY-SEGMENT-CLASS-NOT-REGISTERED`). `_install` creates each class with
`type(name, bases, {"_error_type": …, "__module__": "liquers"})` (or without `_error_type` for a
category), so `__doc__` is `None`. The guide's `DOCS04` blueprint
(`LANGUAGE-INTEGRATION_GUIDE.md` Appendix A §DOCS) checks only `lq.__all__`, not class attributes.

### Scope and Acceptance Criteria

- **AC-1** Every public name is documented
  WHEN the coverage test walks `lq.__all__` and each listed class's own public attributes
  THEN every one has a non-empty `__doc__`
- **AC-2** Coverage cannot regress
  WHEN the coverage function is run over a synthetic class with one undocumented public method
  and one documented one
  THEN it reports exactly the undocumented one, by name, in its failure message
- **AC-3** Every public callable has a signature
  WHEN `inspect.signature` is applied to each public function and method in the coverage set
  (properties excluded)
  THEN it does not raise
- **AC-4** Generated error classes are documented
  WHEN `__doc__` is read on `lq.KeyNotFoundError` and on a category class such as `lq.StoreError`
  THEN the first names its `ErrorType` variant and the second says it is the base of a category

Non-goals: generating or publishing an HTML reference (`py-api-reference`); type stubs (`.pyi`,
the guide's `STUBS`); any renamed, added or reshaped method (`py-metadata-fields-as-properties`);
the `__repr__` text (`py-encoded-reprs`, `py-python-style-reprs`).

### Design Readiness

- **Readiness:** ready
- **Automatic fixing:** eligible, checked strictly. Rule 1: `M`, eleven source files and one Python
  module of one crate. Rule 2: doc comments are a listed kind ("a documentation fix (… doc
  comments …)"), and the coverage test is a listed kind ("new … tests"); a new test that guards a
  documentation property is a test, not a feature. Rule 3: no struct, enum or trait; `_install`
  gains `__doc__` entries, which are doc text only. Rule 4: no signature, method, argument, class or call behaviour
  changes. PyO3 0.30 generates signatures for `#[new]` and methods itself, so step 6 probably
  has nothing to do; where it does, a `#[pyo3(text_signature = …)]` on a constructor only sets
  `__text_signature__`, the introspection metadata `inspect.signature` and `help()` read. The
  callable accepts the same arguments before and after, so it is not an interface change. If a
  callable cannot get a signature without changing its parameters, the fix stops and is
  re-labelled (`auto-fix.md`, "Eligibility can be lost during the fix"). No dependency, feature flag or
  registry change. Rule 5: no open question. Rule 6: everything is in `liquers-py/` (the Python
  module and the test are inside the crate's directory).
- **Leading issue:** None
- **Explanation:** what to write is fixed by the code being documented, and the check is the
  guide's own blueprint extended to class attributes. The generator choice that blocked
  `py-api-reference` does not touch this part.
- **Open questions:** None. Implementation detail: docstring style is a one-line summary in the
  Python reader's terms (no Rust paths), then arguments, result and raised errors in prose, with a
  pointer to the `PYTHON_GUIDE.md` section for semantics.

### Design Dependencies

- `py-api-reference` (needs decision): **required-by**. Its generator reads these docstrings;
  without them it renders bare names. It adds the second half of `DOCS04` (the reference builds).
- `py-metadata-fields-as-properties`, `py-metadata-typed-errors`, `py-encoded-reprs`,
  `py-python-style-reprs`: **overlaps**. They edit the same `#[pymethods]` blocks; a `///` line is
  independent of a `#[getter]`, an error mapping or a `__repr__` body, so conflicts are line-level
  and whichever lands second rebases (T3 rejected). AC-1 then catches a new public name left
  undocumented.
- `py-command-decorator-declaration-keywords`: **overlaps**. Its new keywords are documented by
  whichever lands second.
- `py-query-segment-registration` (needs decision): **overlaps**. Until it lands, `QuerySegment`
  is a known exclusion of the coverage walk; afterwards `__all__` reaches it.
- `py-pypy-ci-job` (needs decision): **overlaps** (weak). These tests also run in its PyPy job.

### Scope Changes

- **2026-10-27, created by split** from `py-api-reference` (its AC-1 to AC-3 and Phase 4 steps
  1-6), so that the eligible part is not held by the generator decision (overlap exclusion E1).
  AC-4 is new here: it makes the `_install` change observable on its own.

## Phase 2: Architecture

### Solution

1. **Docstrings.** A `///` comment on every registered `#[pyclass]`, every public `#[pymethods]`
   item (getters included; a property's doc comes from its `#[getter]`), every `#[pyo3(get)]`
   field (the doc comment goes on the field), `QuerySegment`'s methods (returned to users even
   though the class is not exported), and the three `#[pyfunction]`s, in `liquers-py/src/{query,command_metadata,metadata,error,expiration,dependencies,plan,recipes,environment,context,asset}.rs`.
   Existing public `///` comments written for Rust readers are rewritten for a Python reader in
   the same pass; private items (`_register_command`) are left as they are.
2. **Signatures.** PyO3 0.30 generates `__text_signature__` for `#[new]` and for methods
   (`pyo3-macros-backend` 0.30.1 `pymethod.rs`, `PyClassNewTextSignature`); it has no
   class-level `text_signature`. Where the AC-3 test still finds `inspect.signature` raising, add
   `#[pyo3(text_signature = "(…)")]` on that constructor only, matching its parameters exactly.
   Stop rule: if a signature needs a parameter change, stop and re-label (Design Readiness).
3. **Generated error classes.** `liquers-py/python/liquers/_errors.py` `_install` adds `"__doc__"`
   to each namespace: `f"Raised for ErrorType.{name}."` for a variant and
   `f"Base class of every error in the {category} category."` for a category.
4. **Coverage test.** `liquers-py/tests/test_DOCS_docstrings.py`. A function
   `undocumented(module_names, getattr_from)` returns the missing names, so the test can run it on
   `liquers` and on a synthetic class (AC-2). The coverage set is `lq.__all__` plus, for each class
   in it, the names in the class's own `__dict__` that do not start with `_`; **values are read
   with `getattr(cls, name)`**, not from `__dict__`, because on CPython 3.9 a `staticmethod` object
   in `__dict__` carries `staticmethod`'s own `__doc__` (a false pass) and `inspect.signature`
   raises on it. Enum members (instances of their own class) are skipped. The signature check
   skips properties (getset descriptors, `inspect.isdatadescriptor`), which never have a
   signature. `QuerySegment` is a named exclusion until `py-query-segment-registration` lands.

Rejected: `interrogate` or another source-reading coverage tool (it cannot see a PyO3 extension's
`__doc__`); hand-written docs in `specs/` (they drift).

Known-issue preflight: none block. `PY-METADATA-FIELDS-ARE-METHODS` will turn methods into
properties later; their `///` comments move with them.

### Changes

- `liquers-py/src/*.rs` (the eleven files above): comment lines and, where AC-3 needs it,
  `text_signature` attributes only.
- `liquers-py/python/liquers/_errors.py` `_install`: the `__doc__` entries.
- New `liquers-py/tests/test_DOCS_docstrings.py`.
- Documents: `liquers-py/README.md` `DOCS` row (the docstring half of `DOCS04` passes; the row
  stays `PARTIAL` until `py-api-reference`). `PYTHON_INTEGRATION.md` §8 keeps its "no API
  reference" line, which `py-api-reference` removes.

### Risks

| Risk | Mitigation | Certainty |
|---|---|---|
| A `text_signature` that does not match the real parameters | AC-3 checks it parses; review compares it with `#[pyo3(signature)]` | medium |
| A docstring states behaviour wrongly | One-line summaries taken from the code; semantics by link to the guide | medium |
| The long diff conflicts with overlapping designs | Comment-only lines; whichever lands second rebases | high |
| A dunder or inherited attribute is counted | The set uses the class's own `__dict__` and skips `_` names | high |

Recovery: revert; comments, a docstring dictionary entry and a new test change no behaviour.

## Phase 3: Examples and Tests

### Examples

After the change `lq.Query.encode.__doc__` is a sentence ("The query as text, in the encoded form
`parse` reads back."), `help(lq.Query)` lists each method with its signature and summary, and
`lq.KeyNotFoundError.__doc__ == "Raised for ErrorType.KeyNotFound."`.

### Tests

`liquers-py/tests/test_DOCS_docstrings.py`:

- `test_DOCS04_every_public_name_is_documented`: every name in the coverage set has a non-empty
  `__doc__`; the failure message lists the missing ones: AC-1
- `test_DOCS04_coverage_check_names_an_undocumented_attribute`: `undocumented` over a synthetic
  class with one documented and one undocumented method returns only the second: AC-2
- `test_DOCS04_every_public_callable_has_a_signature`: `inspect.signature` on every function and
  method in the set: AC-3
- `test_DOCS04_generated_error_classes_are_documented`: `KeyNotFoundError` and one category class:
  AC-4

Run:
`bash scripts/test-liquers-py.sh -k DOCS04`.
