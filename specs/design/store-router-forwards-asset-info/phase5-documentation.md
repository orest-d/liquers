## Implementation Summary

`AsyncStoreRouter` (`liquers-core/src/store.rs`) now answers by one rule — **data has one owner,
directories are a union** — and forwards whole-directory questions to a member when it is the only
contributor:

- `get_asset_info` and `listdir_asset_info` are overridden: a member's override (the front-matter
  adapter `design/store-adapters/` plans) is heard through the router. This is step 0.2 (D1) of
  `agent-memory-mvp/execution-plan.md`.
- `is_dir` asks every covering member, not the first; the root, keys above a member and a member's
  prefix at which its owner holds no data are directories.
- `contains` is the owner's answer or `is_dir`, `Ok(false)` for an unowned key instead of
  `KeyNotSupported`, so `AssetManager::get_asset_info` works on a directory above two mounts.
- `get_metadata` of a directory with several contributors lists the router's children, not only
  the owner's.

Private helpers only (`sort_asset_info`, `is_above_members`, `sole_contributor`,
`directory_record`); no `pub` signature, command or format changed.

**Against the request and the approved design.** The request was the issue's two methods. Approved
additions: `contains` (AC-7) in Phase 1, AC-9 and AC-10 at the Phase 1 gate. Added in implementation:
AC-11 (decision 6, option A, chosen by the user after the pre-approval was voided), because composing
children made an empty nested member an error. Omitted: nothing. One departure from a filed issue:
`STORE-ROUTER-IS-DIR-IGNORES-IS-SUPPORTED` asked for routing through `find_store`; the design chose a
union of covering members (Phase 2), recorded in its resolution.

## Important Learning

- First match wins in the router, so a nested member is added **before** its parent; an overlay
  intercepts its file only when listed first. The tests written first failed on this before anything
  else (now in `STORE_SEMANTICS.md` §6).
- An empty memory store, like an uncreated file-store folder, does not report its own prefix as a
  directory. Any code that composes a listing from owners must handle it; the router now does.
- `AssetManager::get_asset_info` asks `contains` first, so a store's `contains` error is a
  client-visible failure.
